## 一、产品概述

### 1.1 一句话描述

**校园资料智能问答助手**是一个基于 RAG（检索增强生成）技术的网页应用：用户用自然语言提问，系统先从本地校园资料库中检索相关内容，再交给大模型生成准确、有据可查的回答。

### 1.2 产品背景

大语言模型存在"幻觉"问题，且不了解本校具体政策；校园信息（选课、图书馆、校园卡、宿舍等）又分散各处。本产品通过"本地资料 + 向量检索 + 大模型生成"的组合，让学生能快速得到关于校园流程的准确答案。

### 1.3 产品价值

- **对学生**：不用翻遍官网/公众号，一个网页就能问清校园流程。
- **对学校**：知识库方式沉淀校园信息，可低成本维护、复用。
- **对项目（课程实训）**：完整体现"AI 大模型 → Python → FastAPI → LangChain RAG"的课程知识点。

## 二、目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 在校学生 | 主力用户 | 快速查选课、图书馆、校园卡、宿舍报修等流程 |
| 新生 | 不熟悉校园 | 从零了解校园常用办事流程 |
| 访客/家长 | 了解学校信息 | 查询图书馆开放、缴费等公开信息 |

> 本产品为课程实训项目，**无需登录注册**，任何访问网页的人均可提问。

## 三、详细功能列表

### 模块 A：网页问答交互（前端 + 接口）

| 编号 | 功能 | 描述 | 输入 | 输出 |
|---|---|---|---|---|
| F-01 | 发送问题 | 用户在输入框输入问题并发送 | 文本问题 | 触发后端问答 |
| F-02 | 显示回答 | 将后端返回的回答展示在聊天区 | 后端回答 | 聊天区新增一条回复 |
| F-03 | 回车发送 | 支持按 Enter 键直接发送 | 键盘事件 | 等同点击"发送" |
| F-04 | 空输入拦截 | 问题为空时提示，不发送 | 空输入 | 弹窗提示"请输入问题" |
| F-05 | 多轮对话 | 记住同一会话上下文，支持追问 | 连续多轮问答 | 回答能结合上文 |
| F-06 | 错误提示 | 后端未启动或请求失败时友好提示 | 请求异常 | 聊天区显示错误信息 |

### 模块 B：RAG 检索核心

| 编号 | 功能 | 描述 |
|---|---|---|
| F-07 | 文档加载 | 读取 `data/` 目录下所有 .txt 资料 |
| F-08 | 文本切分 | 把长文档切成约 500 字/块、重叠 50 字的小块 |
| F-09 | 向量化 | 调用 embedding 模型把文本块转成向量 |
| F-10 | 向量存储 | 向量持久化存入本地 Chroma 向量库 |
| F-11 | 相似度检索 | 根据问题检索最相关的 k 个文本块（默认 k=4） |
| F-12 | 一键建库 | 运行脚本完成"加载→切分→向量化→存储"全流程 |
| F-13 | 索引重建 | 资料更新后删除旧库重建（支持跳过已建库） |

### 模块 C：大模型生成

| 编号 | 功能 | 描述 |
|---|---|---|
| F-14 | 大模型接入 | 通过 OpenAI 兼容接口调用大模型 |
| F-15 | 提示词模板 | 定义系统提示词，规定角色和回答规则 |
| F-16 | 上下文注入 | 把检索到的资料片段拼进提示词一起发给模型 |
| F-17 | 幻觉控制 | 提示词要求"只按资料回答，资料没有就说没有" |

### 模块 D：接口服务

| 编号 | 功能 | 描述 |
|---|---|---|
| F-18 | 健康检查 | GET `/` 返回后端启动状态 |
| F-19 | 问答接口 | POST `/chat` 接收问题、返回回答 |
| F-20 | 接口文档 | 自动生成 Swagger 文档（`/docs`） |

## 五、界面设计要求

### 5.1 整体布局

采用**简洁的单栏聊天式布局**，从上到下依次为：

```
┌─────────────────────────────┐
│  校园资料智能问答助手（标题）      │
├─────────────────────────────┤
│                             │
│   聊天记录区（可滚动）          │
│   用户问题靠右（蓝色）          │
│   助手回答靠左（黑色）          │
│                             │
├─────────────────────────────┤
│  [输入框................] [发送] │
└─────────────────────────────┘
```

### 5.2 交互要求

| 项 | 要求 |
|---|---|
| 消息样式 | 用户消息**右对齐、蓝色**；助手消息**左对齐、黑色** |
| 聊天区 | 固定高度、内容多时可滚动，新消息自动滚到底部 |
| 输入 | 输入框 + "发送"按钮，支持**回车发送** |
| 发送后 | 清空输入框，问题立即显示在聊天区 |
| 空输入 | 弹窗提示"请输入问题"，不发送 |
| 错误处理 | 后端未启动时，聊天区显示"请检查后端是否启动" |

### 5.3 兼容性

- 主流浏览器（Chrome / Edge / Firefox）均可正常使用。
- 适配常见屏幕宽度（页面最大宽度约 700px，居中显示）。

## 六、技术栈建议

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | 原生 HTML + CSS + JavaScript | 无框架，简单够用 |
| 后端 | Python 3.12 + FastAPI + Uvicorn | 轻量、自带接口文档 |
| AI 框架 | LangChain 1.x | 提供 RAG 完整工具链 |
| 大模型 | DeepSeek（deepseek-chat） | 国产、便宜、有 API |
| 嵌入模型 | 硅基流动 BAAI/bge-large-zh-v1.5 | 免费、中文效果好 |
| 向量库 | Chroma（本地持久化） | 免部署、开箱即用 |
| 数据存储 | 无关系型数据库，多轮记忆用内存 | 最小化依赖 |

> 详细选型理由与版本号见《SPEC.md》。

## 七、非功能性需求

| 类别 | 需求 | 说明 |
|---|---|---|
| 性能 | 响应时间 ≤ 5 秒 | 本地检索 + API 生成的总耗时 |
| 性能 | 首屏加载快 | 前端为单页 HTML，无重资源 |
| 安全 | 密钥不硬编码 | API Key 存 `.env`，代码里只读环境变量 |
| 安全 | 密钥不入库 | `.env` 加入 `.gitignore`，不提交到 GitHub |
| 可用性 | 报错友好 | 后端未启动、缺密钥时给出明确中文提示 |
| 可用性 | 部署简单 | 一条命令启动后端，双击打开前端 |
| 可维护性 | 模块化分层 | `rag / llm / api / models` 职责清晰 |
| 可维护性 | 注释充分 | 关键逻辑加中文注释，便于答辩讲解 |
| 兼容性 | 跨浏览器 | 主流浏览器均可使用 |
| 成本 | 低 API 成本 | embedding 免费，大模型按量计费（少量充值即可） |

## 八、验收标准（MVP 完成判定）

1. 后端能启动，`/docs` 能打开接口文档。
2. 前端网页能正常显示聊天界面，能发送问题。
3. 对已入库资料中的问题（如"校园卡怎么充值"），回答准确、有依据。
4. 对资料外的问题（如"学校什么时候放假"且资料无此内容），回答"未找到"，不编造。
5. 同一会话内能进行多轮追问。
6. 全程不泄露 API 密钥。
